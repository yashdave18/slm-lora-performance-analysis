% Abstract
% -------------------------------------------------
\begin{abstract}
We train Pythia-410M on a selected combination of 11 text datasets with LoRA and evaluate its performance and inference costs on a Colab Tesla T4. We explore three primary settings that contrast adapters with 8 and 16 ranks and learning rate values of $10^{-4}$ and $5\times10^{-4}$. The best performing validated adapter with 16 ranks decreases the test perplexity from 23.1134 to 19.6587 (14.95\%) in 244,760 prediction targets with enhancements for all 11 texts.
\end{abstract}

% -------------------------------------------------
% Methodology and data
% -------------------------------------------------
\section{Methodology and data}

Pythia is an autoregressive GPT-NeoX model~\cite{pythia}. We use \texttt{EleutherAI/pythia-410m}. The model has 24 layers, hidden size 1,024, 16 attention heads, a 4,096-dimensional feed-forward neural network and a 2,048-token context capacity. The base has approximately 405.3 million parameters. Training makes use of 256-token chunks.

Dataset includes WikiText-2 raw, TinyStories, AG News, IMDb, Yelp Review Full, Amazon Polarity, CNN/DailyMail 3.0.0, XSum, SQuAD contexts, Emotion, and Rotten Tomatoes. Only natural language fields are utilized: articles/docs for news, context for SQuAD, title+text for Amazon, and text everywhere else. No labels and Q\&A targets are utilized. These are samples drawn from Hugging Face datasets. ID's, subset, and version of sources are provided in the repository configuration and data manifest.

Normalization of Unicode and whitespaces, preservation of 40--20,000 character texts, and canonical text deduplication are required preprocessing steps. Allocation by seed hashing has the probability of 80/10/10 but preserved after source post-processing are 1,000/100/100 texts correspondingly. Thus, preserved ratios differ from 80/10/10. Bounded streaming shuffle is practical sampling and not uniform sampling of all the sources. Data sets for reasoning were not chosen, but contents are not filtered semantically for all incidental reasoning content.

\begin{tabular}{@{}lrrr@{}}

\midrule

Validation & 1,100 & 1,634 & 246,145\\

Tokenization retains entire documents and adds EOS tokens. Length 256 chunking allows for overlap of one context token and ensures that each next-token target is retained precisely once without concatenation of documents. Padding tokens are masked according to position while EOS targets are retained. Manifests contain checksums. Exact deduplication does not exclude near duplicates.

\section{LoRA training and model selection}

The LoRA learns the low-rank updates while the base model parameters remain fixed~\cite{lora}. The target of applying dropout 0.05 and non-trainable biases is the projection matrix of query, key,value from each layer.

For rank 8 $\alpha = 16$ and 786,432 trainable parameters, and for rank 16, $\alpha = 32$ and 1,572,864 trainable parameters. Hence, the ratio $\alpha/r=2$ is constant.

In all main experiments, AdamW optimizer, weight decay 0.01, gradient clipping 1.0, seed 42, batch size 2 with accumulation 8 (16 chunks per step) were used. The auto-mix precision in FP16 was applied to FP32 weights with gradient checkpointing. Cosine learning rate scheduling with 154 warmup steps (ceiling of 0.05 * 3072). Common limitation is 3,072 steps that correspond to about three epochs. The evaluation and checkpoint saving occur after each 100th step and at the end.

The early stopping allows up to five consecutive validations without improvements by 0.001 in validation token loss after the last meaningful best one..

Absolute best-checkpoint selection is performed separately, so that the run could stop early and still make small improvements. Rank 16 at $10^{-4}$ stopped early at 3,000 steps, the other runs reached the limit. Colab interruptions have been restored using persistent checkpoints. Each execution has its own W\&B segment.

\begin{figure}[H]

The improvement in validation perplexity of 0.98\% is observed at rank 16 as compared to ${10}^−-4$ and explains why such parameter can be chosen over others.

Late plateaus were formed due to decayed learning rate without indicating any global convergence. The test at 300 steps with rank 8 is an independent schedule and is not included in budget calculations.

Token loss is summed negative log-likelihood, using natural logarithms, divided by valid prediction targets. Perplexity is calculated as $\exp(\mathrm{loss})$, bits/token is calculated as $\mathrm{loss}/\ln 2$. Sequence loss is NLL summed over sequence length divided by the number of chunks . W\&B logs training loss, throughput, schedule, gradient norm, configuration, checkpoints, and validation metrics, length buckets, examples, rankings.

Final numbers are recalculated from logged metrics instead of screenshots.

\section{Inference benchmark protocol and results}

It consists of four versions (base and three best adapters) with batches 1/2/4, prompt lengths 64/128/256, and autocast FP32/FP16 – 72 combinations. All 72 combinations are warmed up twice and repeated five times, yielding 360 runs. The sequences always produce 64 tokens using greedy decoding with EOS termination switched off. Prompts are not generated based on the tests but validation data. Four validation sources are used for different prompt lengths.

Weights continue to be FP32 in both precisions modes. Adapters are \emph{unmerged}; SDPA and KV caching are enabled while TF32 is disabled. Model loading, tokenization, transfer, warming up, and logging are not included. The throughput is computed as the number of tokens generated over the total timing seconds, and not the prompt tokens. The time to first token was not recorded.

\begin{figure}[H]
    \centering
    \includegraphics[width=\columnwidth]{throughput_by_batch.pdf}
\end{figure}

For length 128, the throughput of the FP32 base model is between 60.27 tokens per second and 220.53 tokens per second for a batch size of 1 and 4, respectively. The throughput of the chosen adapter is from 50.82 tokens per second to 163.36 tokens per second. This is the total throughput since more tokens are generated simultaneously.

AutoCast FP16 performs worse in this case. Possible reasons include the casting itself and overhead associated with small workload start-up; however, they are not decoupled in the current test suite. The weights themselves are FP32; therefore, this test can’t measure full-loaded FP16 vs. FP32 models. Rank 8 is not necessarily faster than rank 16; further testing should demonstrate how rank affects performance.

\section{Discussion and limitations}

LoRA allows for a positive adaptation with fewer than 0.4\% trainable parameters in this experiment. Rank 16 and the higher learning rate enable enhanced validation performance by a little bit; the chosen model shows better test performance. One-seed experiments are executed, without any concern about the training seed. Insufficient run time, early stopping, data sample size and cosine decay preclude conclusions regarding convergence. No evidence of numerical instability or memory problems in the submitted results is reported; runtime disconnections do not constitute a failed optimization configuration.

Unmerged adapters introduce additional inference steps. The merging of adapters and weight loading in reduced precision may affect adapter performance in practice; however, no comparison of the above approaches was conducted. Only five iterations, fixed order of execution, same hardware and four benchmark prompts used for evaluation restrict generalizability of this experiment.
